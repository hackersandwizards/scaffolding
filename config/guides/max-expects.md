# More than five `expect` calls mean a test checks multiple behaviours, several inputs sequentially, or duplicated expectations.

Overloaded tests hide which behaviour failed and repeat assertions already owned by other tests.

Find the fix: identify the single behaviour this test checks. Split distinct behaviours into separate tests, each named for its behaviour, arranging only what it needs, and keeping every input the original test covered. Replace repeated checks or a loop over cases with `test.each`, giving one row per input and expected result. Compare the fields of one result returned by a single call as a whole with `toEqual`. Several tests whose arrange and act lines match and that differ only in which field of that result they assert check one behaviour. Removing an assertion is right only for a verified duplicate. Name the test checking the same behaviour for the same input, break the behaviour once, and watch that test fail. Confirm each surviving test fails when the behaviour in its title is broken.

No fix: splitting into tests repeating one setup for fragments, narrowing the original inputs, or looping over cases to lower the static `expect` count. Hiding assertions in a helper, or packing unrelated checks into an array, object, or `&&`, is no fix. Switching to another assertion API or a snapshot, deleting uncovered assertions, or raising the limit is also no fix.
