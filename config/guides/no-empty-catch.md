# This `catch` block or `.catch()` callback discards every error it receives.

A comment-only `catch` block or an empty promise `.catch(() => {})` hides both expected failures and real bugs.

Find the fix: before narrowing a `catch`, run every environment (browser, server, test) to list absorbed errors. A rethrown error stops following code; in pre-paint scripts, set defaults first and guard only the optional step. Where `try` wraps one call throwing only the expected error (`JSON.parse`), shrink `try` to it and return the fallback. When `try` can fail several ways, match `error.code` (`"ENOENT"`), `error.name` (`"QuotaExceededError"`), or a library class via `instanceof`. If a module throws a plain `Error`, update it to throw a class or code, then match that. Return the fallback and rethrow other errors (omit return if the call has no result). Move handling shared by callers into one function on the owning module returning the result or fallback. Where a contract states failure must not stop work (a lock or cache), one outer caller reports unexpected errors and continues. Remove `try`/`catch` or `.catch()` for unexpected errors; where errors reach users or logs, throw a new error stating what was running with `cause`. Bundle inline scripts or share one inline script. Test the propagating error (in a browser test for inline scripts).

No fix: a longer comment, a no-op (`void error`), or `instanceof Error`. Logging and continuing where no contract accepts the failure, or returning a blanket fallback such as `.catch(() => undefined)`, is also no fix.
